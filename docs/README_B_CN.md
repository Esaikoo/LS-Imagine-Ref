# B 阶段实现与验收报告

更新时间：2026-10-24（再次对照技术方案复查）。基于本地 esaiko-apm 分支的 A v2（提交 7b0c20b）及提供的完整技术方案、B 实现包。

## 结论

B 已从压缩包中的“历史图片检索 + A 条件输入”扩展为“关键帧库 + 循环搜索记忆 + A/Actor/Critic 条件化 + 普通/跳跃想象中的记忆预测”。统一训练入口仍为 scripts/train.sh。

这是 B 的工程实现与短测验收，不是 1M 步效果结论。正式训练仍需用 A-only 和 A+B 的同预算实验判断收益。C 的搜索策略和主动反馈奖励尚未实现，本次也没有改动服务器或提交 Git。

## 2. B 是为了什么

A 比较“接下来做哪一段动作可能得到更好的观察”。B 为这个判断提供“以前看过什么、搜过多久、哪里可能重复、历史线索多久以前出现”的上下文，并让 Actor/Critic 的想象学习也使用这些历史信息。

实际执行的动作仍是原来的 12 个离散动作。第 13 维仍只用于世界模型内部的跳跃标记，不会发给 Minecraft。B 不额外创建一套真实动作规则，也没有新增 C 的探索奖励。

## 3. 新增数据、保存位置及用途

| 数据 | 来源与作用 | 是否持久保存 |
| --- | --- | --- |
| search_place_id、search_place_valid | 训练环境的位置按 2 米分格、视角按 45 度分格，生成 Episode 内的编号；只监督地点区分 | train_eps/*.npz；旧轨迹缺失时为未知，eval 为无效 |
| search_revisit、search_visible、search_new 等 | 复用 A 的真实射线事件与有效性掩码，监督 B | 沿用 A 的 NPZ 字段 |
| log_b_revisit_prob | B 对当前场景重访的预测概率 | train/eval NPZ |
| log_b_memory_used、log_b_memory_slots | 此次判断是否已有历史、当前用了几个槽 | train/eval NPZ |
| log_b_keyframe_indices | 默认每步 16 个数值索引，可回查本 Episode 的 RGB/热力图 | train/eval NPZ；空槽或尚未启用 B 的行是 -1 |
| log_b_observation_index | 该条动作日志所基于的观察帧号 | train/eval NPZ；用于说明动作与后继观察的时间对齐 |
| search_b_prefix_*、search_b_history_*、search_b_real_first | 采样时重建的关键帧、时间/访问统计、近期历史动作、真实重置标记 | 仅为训练批次上下文，不逐帧重复写入 NPZ |
| B 的网络参数和优化器状态 | 编码器、GRU、预测器、证据头、衰减率，以及增宽后的 Actor/Critic | latest.pt，新增 search_b_version=2 |

没有把真实坐标或目标坐标拼入 Actor、A、B 或 RSSM。地点 ID 是监督标签，不是检索输入。策略入口会先去除所有 search_ 字段，记忆只使用可见 RGB、热力图、动作历史和自己的状态。

NPZ 中第 t 行包含第 t 次动作的结果观察，因此该行的 B 决策日志基于第 t-1 帧。索引均为同一文件内的零起始观察行号。重放训练按完整过去重新选帧，不依赖旧网络保存的隐藏向量，也不读取尚未发生的观察。

在线记忆只在当前 Episode 内持续，真正重置时清空，不跨新世界共享。latest.pt 保存可学习参数，不保存正在运行的 Minecraft 世界、GRU 隐状态或活动 Episode 的瞬时关键帧库；它不是逐帧精确恢复运行现场的快照。

## 4. 训练流发生了什么改变

1. 与环境交互：更新 RSSM；用当前观察、历史库和上一实际动作更新 B；Actor 使用 RSSM+B；A 比较候选动作时也接收 B。
2. 保存真实轨迹：保留原观察、动作、奖励、A 标签，增加地点监督和 B 的少量数值日志。
3. 采样：仍取原长度的 RSSM 训练窗口，额外重建其之前的关键帧库，并用最近 128 步历史预热 GRU。历史长度不是 Episode 记忆库的保留上限。
4. 模型优化：原 LS-Imagine 损失 + 原 A 损失 + B 损失。B 默认是重访损失 + 0.25 × 证据损失 + 0.1 × 地点损失 + 时序预测损失。B 总权重和时序权重均可配置。
5. 策略优化：原奖励、内在奖励及 Actor-Critic 算法继续使用；其输入变为 RSSM+B，普通和跳跃想象都预测下一记忆。
6. A 的损失也能通过记忆输入训练 B。A 适配层零初始化，因此第一轮先学习适配权重，随后梯度进入 B；没有将未执行分支的自预测当成真实标签。

B 使用的视觉压缩描述为 8×8 RGB 加热力图，共 256 维，再经过可学习编码器。地点匹配只使用 RGB；被检索的历史热力图在编码前随时间衰减，避免旧线索经原始特征绕过衰减。访问次数和场景 RGB 保留，候选目标、负面证据与歧义统计按同一衰减率更新。关键帧选择使用固定规则，检索表示、信念更新及预测网络可学习。真实记忆更新使用视觉描述；RSSM 特征在 A、Actor/Critic 和想象记忆预测器中与记忆结合。

## 5. 记录哪些指标，怎么判断有效

原 LS-Imagine、A 的全部实际产生标量继续写入 metrics.jsonl、TensorBoard，以及启用时的 W&B。终端仍以既定四项为重点；这不是保存白名单。原 model_loss 保留原世界模型损失口径，B/total_loss 单独记录 B 的损失。缩放、跳跃等条件性指标只在对应计算发生时出现。

| 阅读优先级 | 指标 | 怎么看 |
| --- | --- | --- |
| 首先 | eval_success | 同任务、预算、训练/评测种子与回合数下，A+B 是否优于 A-only |
| 首先 | eval_first_success_step | 结合成功率看是否更快完成任务；失败回合记为时间上限，不能当成仅成功回合平均耗时 |
| 行为解释 | eval_search_rate | A 宏动作介入比例；B 对普通 Actor 的影响没有独立“接管率”，此值不是 B 使用比例 |
| 学习检查 | A/prediction_loss | A 预测是否稳定学习；单独下降不证明成功率提高 |
| B 辅助 | eval_b_revisit_rate | B 预测概率超过 0.5 的比例，只统计已有历史的观察；不是环境真值，越低也不一定越好 |
| 故障诊断时 | B/revisit_loss、B/revisit_brier、B/place_loss、B/consistency_loss | 检查重访校准、地点区分和记忆预测；配合对应有效样本数，避免将缺标签产生的零损失误认为学好了 |

其余 B 指标也完整保存：B/revisit_valid、B/revisit_positive_rate、B/evidence_loss、B/place_valid、B/evidence_decay_rate、B/transition_valid、B/total_loss，以及 train_b_revisit_rate。

最重要的比较是同预算的 A-only 与 A+B，而不是 B 自己的损失下降。固定 A+B 检查点屏蔽记忆输入，可以判断模型对记忆的依赖；它不能替代从头训练的消融，也可能产生输入分布变化。没有训练特权标签的 eval 中不能把预测重访率当作真实重复覆盖率。

## 6. 训练入口与消融

激活原 ls_imagine 环境。1M 启动风格保持如下，仅增加 A_MODE=ab 明确选择 A+B：

```bash
TASK=harvest_sand
mkdir -p logs/train/$TASK
A_MODE=ab nohup bash -c "sh ./scripts/train.sh $TASK && shutdown -h now" \
  > logs/train/$TASK/train_$(date +%Y%m%d_%H%M%S).log 2>&1 &
```

该命令仅供用户在服务器正式启动，本次没有执行。

| 选择 | 命令前的环境变量 | 结构 |
| --- | --- | --- |
| 原 LS-Imagine 对照 | A_MODE=off | A、B 都关闭 |
| A-only | A_MODE=full | 沿用此前 A 默认行为 |
| A 损失消融 | A_MODE=loss_only | 学习 A，关闭 A 的真实动作介入，B 关闭 |
| B-only | A_MODE=b | 原 Actor/Critic 使用 B，A 关闭 |
| A+B | A_MODE=ab | 两个模块一起训练和行动 |

未设置 A_MODE 时仍为 full（A-only），避免原有启动命令静默变成另一个实验。服务器默认日志目录为 /root/rivermind-data/mine/projects/tb_logs/LS-Imagine-Ref/<模式>/<任务>/seed_0/<时间戳>，LOG_ROOT 仍可覆盖。

默认 seed=0，单次命令只训练一个种子；不自动轮换种子。可按原方式追加 --seed N --env_seed N。正式对照需要显式统一地图和评测设置；原默认 env_seed=-1 不代表锁定所有评测世界。

同一 A+B 检查点的记忆输入屏蔽参数为 --search_b_control False，或在 apm_ab 后叠加 apm_ab_memory_off。A、Actor、Critic 的 B 输入都屏蔽；网络结构保留，允许严格加载同一权重。关闭 A 的行为可用 --search_a_control False。结构性地移除 A/B 应分别从头训练相应模式，不能把不同输入尺寸的检查点硬加载。

旧 A v2 检查点可在 B 关闭时继续评估；A-only 权重不能直接当作完整 A+B 权重加载。压缩包原 B v1 与本次 B v2 结构不同，也会明确拒绝误加载。

正式入口仍新建带时间戳的实验目录，不是已有 160k 等实验的自动续训命令。同步代码不会改变服务器上已启动进程的内存代码。

## 8. 实现边界

- 16 个槽位是有限的关键观察摘要，不是全世界地图；视觉相似区域仍可能混淆。地点标签是粗粒度位置/视角分格，不是完美的地点真值。
- 候选目标、负面证据和歧义统计仍来自热力图代理。GRU 的事件头由真实训练标签监督，但没有完成 C 的目标验证与反馈策略，不能声称彻底修复热力图误识别。
- 关键帧库从整段过去精确重建；训练 GRU 用有限的 128 步 burn-in 近似在线完整历史状态。没有逐窗口重算整个 Episode 的 GRU，也不对 128 步之外反向传播。保留的老关键帧仍能被检索。
- 随机预填充时没有尚未创建的 B 网络；B 首次接管时从其可见观察开始积累在线状态，训练回放可使用已有预填充历史。这是冷启动差异，数值索引已单独校正。
- 想象记忆的多时间跨度监督限于真实训练窗口内；远超窗口长度的跳跃仍存在外推误差。当前缩放后状态的记忆由预测器估计，不伪装成已获得真实未来观察。
- 动态目标证据衰减率可学习，羊毛任务采用更快的初始值；动态目标搜索是否改善仍需实验，不能只凭设计保证。
- B 支持当前的 greedy/random 探索配置；Plan2Explore 的额外 Actor 接口尚未改造，启用 B 时会明确报错。
- 本次没有实现 C，没有跑 1M、多种子统计或正式网络规模的长时显存/吞吐评测。短测成功不等于收益已证实。

## 再次复查（2026-10-24）

结论应分开理解：B 的核心结构和训练/执行链路已经落地，短测可以验证这些链路可运行；B 的搜索收益、长期稳定性和方案中的全部研究能力仍不能由短测担保。本次检查没有改动服务器、提交 Git 或启动 1M。

### 本次确认并修复的问题

1. **旧目标证据能绕过衰减。** 原实现只衰减了候选证据统计，关键帧热力图仍直接进入编码器；而地点相似度也混入目标热力图。同一地点中目标出现/消失会改变“是否同一地点”的匹配，旧目标证据也仍可能通过特征影响决策。本次把地点地址与证据内容分开：地址只用 RGB；历史热力图先衰减再编码为检索内容，负面证据和歧义也衰减，保留静态 RGB 与访问次数。原始 NPZ 和关键帧内容不被原地篡改。
2. **缺少历史时存在静默遗忘路径。** 原实现用 RSSM 的 is_first 判断是否可以从空记忆训练；该字段会被随机采样器人为设为 True。本次要求显式提供 search_b_real_first；只有已确认的真实 Episode 起点允许空历史，随机截取的中段必须提供历史上下文；还检查前缀的槽位尺寸。

两处问题都通过新增测试在修复前复现，并在修复后通过。没有新增模型参数或改变 Actor/Critic 的输入尺寸，B 检查点结构版本仍为 2。已有 B v2 权重在结构上兼容，但检索计算已修正，前后训练/评测应标记代码版本，不能当成算法完全相同的曲线。

### 与完整技术方案逐项核对

| 方案要求 | 当前状态与判断 |
| --- | --- |
| GRU 搜索信念 + 128 维状态 + 16 个关键帧槽 | 已实现，默认尺寸也完成真实模型的 CPU 联合更新 |
