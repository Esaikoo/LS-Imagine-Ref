## 能定位到哪里，不能确认什么

证据已将失败定位到环境/模拟历史的可复现性，尚未定位到某个底层机制。画面可见动物，实体交互是候选解释；模拟时序、未观测环境状态等也可能参与。当前遥测只记录位置/朝向、物品和健康，未记录实体接触、速度和模拟tick，不能断言是动物撞人或某个时序bug。

本地`goal_control.Session`保留每次真正的incoming与原生事件；动作wrapper存在sticky jump，但本次原生动作序列全部一致，不能只凭sticky机制认定动作不一致。相同动作序列也不足以证明两次模拟状态完全相同，这一点已经由本次实际位置数据证实。

不建议为猜测的原因删除动物、瞬移玩家、复制RSSM或修改观测；这些做法要么改变任务分布，要么无法恢复整个环境状态。若将来实现完整模拟状态快照，应作为另一条方案独立验证；当前代码没有提供经验证的完整快照恢复路径。

## 建议的下一步：新随机起点评估，停止复现门槛循环

要回答的问题应改为：在同一任务和预先声明的起点生成过程下，目标条件worker是否比无目标worker更能向指定视觉目标移动。无需每个独立环境都重现同一条参考历史。

新设计需作为独立协议和输出目录实现，不能把旧FAIL改成PASS：

1. 提前固定真实视觉目标图像/目标库和模型第200步。不根据本轮控制结果挑选目标；目标是视觉条件，不再声称它们是每次实际起点的两个分支终点。可复用已有完整真实目标来源，不需要再次采集一对严格重放参考。
2. 提前固定环境初始化/前缀过程、预算和随机组别顺序。每次fresh reset都保留自己的完整真实历史、状态和动作；在共同前缀完成后执行已预声明组别，不将一次测得的RSSM复制给其他组。
3. 先比较有目标残差、独立无目标残差和交换目标三个条件。冻结底座/零目标等已有离线消融保留，第一轮不必再付六组真实环境开销。可先用3组×2目标×2重复=12次检查接口和行为；一个世界的两次重复只用于描述，不构成统计结论。
4. 对所有正常执行trial记录初始位置、朝向、RGB/heatmap、目标距离和结束结果。位置/RGB差异作为环境波动和起点平衡诊断，不根据“是否接近某条参考历史”挑选纳入样本；任务/视觉协议、有效动作、真实reset/因果历史、环境错误检查仍保留。
5. 同时报终点目标距离、相对本次自身起点的距离变化、两目标偏好变化、初始分布平衡和视频；检查交换目标是否改变去向。若初始分布明显不平衡或环境波动掩盖收益，首轮结论应为不确定，后续再增加预声明世界/重复，而不是以12次宣布控制有效。

保留全部已计划trial和环境错误计数，不按终点挑样、不重试至成功、不把同一世界重复当成独立世界。单纯跳过当前`gl.require(start_result['passed'])`不足以实现此方案：目标来源、比较对象、随机化单位、纳入规则、报告解释和格式都要同步更新。

后续进展：此新协议已完成本地实现，服务器待验收。参见 [独立起点随机分组的两步运行说明](t05_random_control_acceptance.md)。当前停止旧prepare/evaluate与全部旧剩余重复；模型和T04缓存保留，不重训，不推进T06。本文件保留当时失败的原始解释。
