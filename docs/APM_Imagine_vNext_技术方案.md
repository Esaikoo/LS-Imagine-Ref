# APM-Imagine vNext：以任务完成为主线的 ABC 修订方案

日期：2026-10-30。状态：已完成本地实现、CPU/GPU与MineDojo短测；完整1M尚未执行。

依据：原完整技术方案、ABC 约280k失败报告、本轮RTX3090只读短测。下一轮允许从头训练1M，不以旧ABC权重初始化新模型。

## 1. 推荐路线与边界

**保留原LS-Imagine任务学习主干；让A/B服务独立的高层C；补齐发现、接近、对准、交互验证闭环；移除昂贵历史重建和预测回报对低层Actor的直接干扰。**

仍保留三个研究目标：A预测不同行动的观察后果，B持久维护搜索证据，C利用真实反馈学习行动选择。这是基于失败证据修订完整ABC的连接方式，不是继续堆叠模块。

可以保证工程上的梯度隔离、合法输入、预算记账和动作语义一致；**不能保证任意随机种子下1M必然提高成功率**。有限样本、视觉误差和深度网络不满足无条件保证。理论依据、具体可修缺陷和需要实验验证的假设必须分开。

## 2. 失败依据与方案制定时的补充证据

旧续训54回合成功2次，161k至281k最近39回合全败。211k后24回合19回合见过真实沙子；4784个前态可见步骤中，Actor仅提出38次攻击，实际执行31次。主要断点在任务Actor，而非C替换了大量本来正确的攻击。

本轮发现原任务实际采用sticky_jump=10：一次jump后的九个命令仍带jump+forward，包括attack、转向和noop。按wrapper语义重建54回合：

| 项目 | 数量 |
| --- | ---: |
| jump命令 | 14038 |
| 实际含jump控制 | 23487 |
| 粘滞额外跳跃 | 9449 |
| attack同时被强加前进 | 1066/5354 |
| 俯仰命令被限幅为不转 | 6558 |

这是确定性控制语义重建，不是物理重跑。它放大跳跃和对准困难，但不能替代Actor不提议攻击的主因。

在两个真实失败历史上，使用281442权重重建相同RSSM状态，对比正常B与零B：可见步骤两种输入的攻击mode均为零。零B是分布外机制探针，重建随机状态不同于历史原状态，不能用于断言B无影响；它不支持“关B就能修好旧权重”。

## 3. 总体结构与原主干保护

数据流：

    RGB/热图 → 原Encoder/RSSM → 原任务Actor/Critic与想象学习
                           └→ stop_gradient(z) → A、B、C
    历史原始关键帧 → B → A候选后果预测 → C选项学习
    Actor提议、A预测、B记忆、执行器状态 → C → 统一实际执行
    真实结果 → 原Replay → 分别训练原主干、A/B、C

约束：

- 原Actor/Value的输入维度、参数形状、原奖励和原想象目标保持原版；不拼B。
- 原任务奖励和原内在奖励仍保留；不加A预测的新颖性、重访或搜索bonus。
- A/B/C独立优化器且参数集合不重叠，读取停止梯度的RSSM特征。A/B可联合监督一次反向、分别更新各自参数；C读取A/B输出时detach，不能靠Q损失篡改预测含义。新损失对原Encoder/RSSM/Actor/Value梯度为零。
- B仍影响A和实际高层策略C，不是仅记录日志。
- 默认移除C虚拟Dyna训练及对低层Actor的预测奖励回灌。A预测仍实际参与候选比较。
- ABC会改变真实采样分布，不能因此宣称训练结果与原版完全相同。约20%完整训练回合只执行基础策略，维持数据覆盖；全部计入1M。
- 原LS自身热图误识别仍可能发生；需要视觉校准和真实交互验证，不能只靠隔离梯度。

与原文的明确调整：撤回“B直接拼原Actor输入”和“探索收益直接改原Actor回报”。记忆条件化和真实反馈学习移到独立高层C，原低层Actor-Critic仍负责原任务学习。

## 4. 统一执行器：先修命令与实际控制不一致

默认保留原sticky_jump=10、repeat=1、相机限幅及12动作，不静默改变环境难度。

将确定性转换抽为环境与规划共同使用的函数：

    requested command + own actuator state
        → applied controls + next actuator state

own actuator state只由自身历史和公开配置确定，包括粘滞剩余步数、wrapper俯仰计数、上一实际控制；不读取位置、射线或目标坐标。

候选先经同一转换：过滤俯仰限幅no-op；只有实际控制序列、真实持续时间和结束执行器状态均相同才合并。jump与noop当步可能都在跳，但会留下不同的粘滞计数，不能仅按当步控制去重。A必须知道起始执行器状态和实际控制；Replay同时保存请求、最终命令、执行后的控制。13维内部jump标志继续只用于原想象转移，不能作为真实探索动作。

如果以后选择attack/use取消粘滞跳跃，必须作为共同环境协议，同时修改基线和所有消融，历史实验只作参考。本版不默认改变该语义。

## 5. 任务阶段与交互自救

| 阶段 | 允许行为 | 目的 |
| --- | --- | --- |
| SEARCH | Actor、左右短扫描、短前进、转向前进 | 找有效观察 |
| APPROACH/ALIGN | Actor、短接近、有限对准 | 保住目标、靠近并瞄准 |
| INTERACT | Actor、settle、任务合法短交互 | 验证并完成采集 |
| RECOVERY | Actor、短转向/退让 | 处理无进展与重复控制 |

阶段只使用A视觉预测、B、真实合法奖励和自身控制历史。进入/退出有短迟滞与最大占用时间，不以单帧热图决定。

交互验证属于C的选项，不增加第四大模块：

- 采沙：预测准星对应目标、在可交互距离内，执行器稳定后尝试1—2步attack。
- 原木/矿石按工具与破坏时间设置有界burst，不能直接套两步。
- 水和羊按任务语义使用use/工具操作，不统一强制attack。
- 同一候选证据无进展最多两次短burst后，至少冷却20步并要求新的视角/接近证据才重试，避免无限攻击锁死。
- 一次没拿到物品不证明此地无目标，不能生成永久负证据。

settle不触发新jump，让已有计数自然归零，最多九步。noop期间已有sticky仍可能前进，**它不是即时刹车**；要结合实际转换和短时视觉风险，危险/不可信时回Actor。所有额外控制单列占比并计入预算，不能藏在Actor比例中。

原Actor提出攻击/use时，保护其执行，不以“连续超过两步”自动放开无关探索。若长期没有真实进展，交由受限恢复流程，而不是永久保护空打。

## 6. A：从可见预测补齐可交互后果与动作差异

### 6.1 输入与输出

输入：stop-gradient RSSM特征、B记忆、候选实际控制、起始执行器状态、阶段、剩余预算。

当前观察头只计算一次：

- visible：视野内有目标。
- center_target：准星方向是目标。
- reachable：与center_target对应的同一个准星命中目标是否处于实际交互距离；不能用视野中另一个近目标拼接证据。
- 执行门控使用联合center_interactable预测/联合校准，不能直接相乘两个独立边际概率。
- 可选相对目标方向，用于小幅对准；热图强度不能当距离。

动作条件头：

- 未来紧凑观察特征。
- 新观察、首次发现、丢失后再发现、明确离开后返回。
- 未来可交互性、真实任务进展、无进展/受阻。

未来特征可使用原RSSM特征的固定、版本化低维投影并停止梯度；避免预测器和可学习目标共同坍缩成常数。

实际执行默认K3。共享动作编码与干路直接产生K3预测；H8只作为低频真实序列辅助监督，建议每四次更新一次。线上不生成八步再截三步。中断、交互和settle按真实长度监督，不能把没执行的后缀当真实结果。Actor选项保持逐步真实观察闭环；其想象续行动作只是预测近似，若与后来真实执行不同，不能当已兑现计划校准。A用实际序列监督，C用实际选项结果学习。

### 6.2 标签、损失与采样

训练时中心射线、真实交互距离、任务规则用于center/reach标签，策略推理只用正常RGB/热图和历史。任意32米内看到目标不等于可采集。

进展来自真实reward/success或审计的真实物品变化；缺失为unknown。当前最终策略观测没暴露原始inventory，不能偷偷加入策略。工具条件只能来自合法任务配置或正常视觉/历史预测，无法确认则unknown。

损失包含未来特征、事件、可交互性和真实进展；按各自valid掩码计算，不跨reset/terminal。

罕见正例、转折窗可过采样，但必须按抽样概率校正，或在自然频率独立回合集上重新校准；同一world/重置组不能拆散泄漏到训练与验证，分组信息无法恢复时只称回合留出而非地图独立。不能将balanced BCE直接解释为自然概率。

普通轨迹只监督执行动作。候选差分/排序真值仅来自同起点同前缀、校验一致、实际执行的配对分支。不同地图或模型虚拟结果不是配对标签。

### 6.3 可靠性

使用三个小bootstrap头，联合检查选项/阶段/时长的真实支持、正负例和近邻覆盖、校准误差及头间分歧。

大量零奖励不代表未执行候选可靠。分歧是代理，不是真实全状态误差界。缺正例、分布外或强分歧时，不把预测回报送入TD目标或任务Actor；降低该选项执行资格。

## 7. B：整个Episode的有限记忆，不重建128步大模型

保留16槽。保存Replay帧引用、插入/更新时间、访问/观察历史、目标证据、尝试交互及结果、不确定性与有效性。

小型独立CNN编码RGB+热图，输出128维key/value；RSSM只作停止梯度的query，注意力产生128维记忆。取消历史大Encoder/RSSM和循环belief烧入。长期状态由显式关键帧与证据集合维护，不宣称是完整世界地图。

入库不再仅用RGB均色阈值。结合可学习场景匹配、空间结构、相机/动作一致性和证据变化；不确定相似场景不强行合并。保留新区域、候选目标、不确定观察的空间，防高热图永久占槽。

训练包括地点区分、返回事件、历史目标证据保持、交互尝试结果；不只训练重访BCE。动态目标证据单独衰减，静态访问历史不随同遗忘。

恢复方式：

1. 采集时记录槽写入/替换事件，每64步存紧凑索引与元数据快照。
2. 训练从最近过去快照恢复，最多重放63步写入事件。
3. 采集时的入库决定不可变，不能用更新后的匹配器改写历史。
4. 按episode/frame去重同批关键帧，用当前小CNN编码，不缓存无版本的学习latent。
5. 槽引用必须早于当前帧，先读再写；空记忆输出精确零。
6. 真Episode边界清空；拼接窗口按真实边界恢复，检查引用所有权。

### 重访、停留和负证据

return_after_departure是已知离开/退出视野足够时间后返回，在返回当步记一次；连续面对同一沙地是dwell，不是return。

未知观测间隔不能证明离开，valid=False。dwell_no_progress单独用于SEARCH/RECOVERY诊断，不处罚低层Actor的采集。

负证据只表示某次观察与动作没产生预期结果，不证明整片区域永久无目标。旧Replay缺射线几何/中心距离，不能补造新标签；新训练使用新label/protocol版本。

## 8. C：用真实反馈学习剩余预算内成功概率

### 8.1 决策网络与候选

C采用独立小型离散SMDP双Q及目标网络，实际策略由Q选择；省去额外高层SAC Actor。原任务Actor-Critic保留。

输入：stop-gradient RSSM、B、A预测、阶段、执行器状态和剩余预算。Actor始终可选。

SEARCH保留左右扫描、前进、转向前进，默认去掉无目标依据的上下扫描；必要俯仰只在ALIGN用可信方向预测启用，一个小步后冷却。

INTERACT提供Actor、settle和合法交互验证。只有Actor可选时直接返回，不计算候选；但选项边界与反馈仍记录。

### 8.2 学习目标

C主价值是剩余Episode预算内最终成功概率。首次成功奖励1，失败/超时终止0，状态包含剩余预算，有限时域gamma=1。

选项内成功target=1；失败或预算耗尽target=0；其余从真实结束状态和合法选项的目标Q bootstrap。真实持续时间要准确扣除。

双Q各用sigmoid输出[0,1]，明确采用在线双Q最小值选择合法后继选项、目标双Q最小值评估所选项的clipped规则；这是保守近似而非置信下界。后继mask用真实结束阶段、执行器、剩余预算和支持。剩余步数不足时截短或禁用选项，记录真实时长，目标网络软更新。

短窗口未见成功不是整回合失败；不完整保存、环境通信错误和真实终止不能混为失败标签。原低层Actor的折扣、内在奖励和时间截断口径保持原样，C有限预算成功价值独立处理。

新颖性/返回信息用于A/B监督、训练候选采样、任务价值相近时的次级依据，**不再构成每步固定负罚**。默认不把A虚拟回报写进C的TD目标，也不训练低层搜索bonus。

### 8.3 数据不足与占用约束

早期训练仅在SEARCH中按记录概率做少量分层选项采样，覆盖可执行方向，避免高层再次长期93%选Actor。探索实际步预算从约5%到10%，上限15%；恢复/settle/交互验证也独立记账。默认新增控制在滚动100步内总占用不超过25步，settle最多12步；有真实任务进展的继续交互单列记录，不能用它隐藏无进展接管。

eval不使用随机探索。选项需局部支持、可信预测及明确任务价值/有效观察依据；证据不足回Actor。缺乏可靠任务价值时，只能说明行为占用受限，不能宣称安全改进。

选项持续导致限幅no-op、丢失目标或预测偏离，局部禁用并补真实数据，不以全局Loss替它背书。

真实反馈来自日常执行。少量同场景对照用于候选排序验证，不默认频繁新建Java长分支。保留世界、前缀、执行器、物品/生命、射线与渲染容差校验，不按最终成功筛场景。训练型对照所有真实步、前缀都计入1M，reset墙钟成本单列。

## 9. 理论依据：为什么这版更对准成功率

成功链同时包含发现目标和发现后的完成。提高发现率但破坏采集，最终胜率仍会下降；新方案分别保护后半段、优化前半段，且增加交互验证，不能只追求新画面。

设x含充分历史、执行器状态和剩余预算，pi0是固定基础策略，Q0(x,o)是执行option后返回pi0的成功概率，Actor始终可选。若候选和基础价值均有真实误差界epsilon，且：

    Q_hat(x,o) - V_hat_0(x) > 2 * epsilon

则候选真实优势为正。在充分状态、准确价值评估、固定基础策略与有限时域等条件下，可按策略改进论证非下降；有正优势状态被访问时可严格提升。

更直接的理想依据是：只要所有状态都保留Actor，纯基础策略就在可执行策略集合内，所以该集合的理想最优成功率不低于基础策略；若真实正优势状态在指定初始分布下以正概率可达，可以严格提升。这是策略空间与目标的性质，不是有限训练网络的成绩保证。

上面的固定pi0评估Q，与第8节max-bootstrap学习的控制Q不是同一个价值；本版不把控制Q差值当作可证明的基础优势或安全证书。要实际使用该安全定理，需要另行可靠评估同一固定后续策略，当前不为此增加额外网络。

压缩RSSM/B未必是充分状态，bootstrap分歧不是误差界，训练中的基础Actor也变化。因此该论证是设计依据，**不是本项目1M保证**。“证据不足保留基础策略”参考[SPIBB](https://arxiv.org/abs/1712.06924)，不能直接套其有限MDP保证。

第一版默认不加额外探索奖励。若后续C稀疏学习受阻，可单独对照势函数：

    F = gamma^duration * Phi(x_next) - Phi(x)

真实终局Phi=0，整个Episode冻结Phi版本，或同一目标轨迹及bootstrap统一用同一快照，按真实持续时间记账。开启整形时须另行处理价值范围，不能直接把可为负的整形回报塞进当前[0,1]成功概率TD头。标准条件下保持最优策略，不保证有限训练更快，依据[Ng等，1999](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)。有限时域gamma=1时，原地保持同一Phi不会每步受罚。

不同时重新打开势函数、Dyna和Actor预测奖励。[MBPO](https://arxiv.org/abs/1906.08253)支持谨慎控制模型数据偏差，不证明本项目开启Dyna必有效。

## 10. 从头1M的训练安排

主种子0、原任务/环境配置、原模型容量保留。1M包含原2500 prefill、正常训练、训练探测、恢复、settle与训练型分支；评测独立计数并报告成本。不使用旧ABC参数或旧标签伪初始化。

| 区间 | 行为安排 |
| --- | --- |
| 0—25k | 原LS主导；A/B真实监督；C少量受限SEARCH采样积累支持；未校准交互头不强制攻击 |
| 25k—100k | 启用局部可信搜索与采沙交互验证，探索约5%；持续真实反馈 |
| 100k—1M | 任务价值主导选择，探索约10%、最高15%；约20%基础策略完整回合保护覆盖 |

这些是初始超参数，未被短测证明最优。启用按局部支持和校准判断，不要求全局Loss达到任意阈值，不因支持不足静默延长预算。

训练采样、eval取mode的原方式保留，持续比较分布；不能只改eval为随机来掩盖主要策略退化。

## 11. 数据、指标与消融

## 12. 性能约束与实施顺序

性能约束：

- B只恢复槽快照/事件，不重建128步RSSM；批内去重关键帧。
- 先按需取窗口，再复制/搬运，避免deep copy整Episode zoomed float64。
- A当前头一次，K3加低频H8，不重复八次整网。
- C唯一候选直接返回；Actor对照直接K3；起终点批量计算，避免逐记录GPU标量同步。
- 默认移除Dyna、六项预测回报回灌和原任务想象中的B循环。
- 仅在数值验证后使用AMP，不能牺牲valid掩码或改变预算换速度。

实施顺序：执行器/新标签与日志 → 原主干隔离 → 轻量B → A可交互性与校准 → C阶段与真实反馈 → 保存/恢复/统一入口。

必须扩展现有tests/test_search_a.py、scripts/test_a.sh，不增加重复启动脚本。正式训练仍由用户用scripts/train.sh启动。

## 13. 进入长训前的针对性验证

不用大量随意短训练代替定位，至少检查：

1. 新损失对原主干梯度零；ABC off恢复原前向与初始化随机流；无oracle输入。
2. 连续看同场景不判返回；明确返回只记一次；未知间隔valid=False；限幅候选过滤。
3. 正式batch16/length32、槽因果引用、reset/拼接窗口、保存恢复、有限数值正确。
4. 少量固定新场景验证：可见但够不着、贴脸可采、跳后交互、天空/浅色误报、无进展恢复。
5. 正式容量有限联合更新和环境交互，确认优化器真更新、完整耗时/显存、真实采集和恢复，不把CPU通过说成行为已验证。

若仍贴脸跳跃不采、无限攻击或预算失控，先修具体失败；不靠另一次1M发现这些问题。成功率不必立刻超过作者，但至少不能以更多接管或更低Loss冒充行为收益。
