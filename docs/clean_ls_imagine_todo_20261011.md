# 原版 LS-Imagine 重启研究 Todo

日期：2026-10-11。全新计划，全部实验待执行。旧 T00–T05 文档、失败和 checkpoint 保留作历史资料。本次仅整理文档，没有修改模型代码或服务器。

## 研究主线

恢复并复现官方 LS-Imagine，保留原任务相关热力图、MineCLIP 奖励、U-Net、RSSM 和训练主干。先排查环境与反馈，再研究“真实执行约束的长程想象”：让选出的子目标既有任务价值，又能由真实动作达到。

分开回答三个问题：原版是否正确复现；反馈是否区分任务进展与失败；固定感知/奖励后，可执行子目标与跨步预测是否改善成功率和样本效率。通用热力图、NACLIP、P85 放到后续独立消融。

原版回放可能包括大量探索失败，不能自动视为专家数据，也不保证更好的改进效果。不能承诺一次达到 T06。

## 关键事实与剪羊毛诊断

原论文附录 A 的剪羊毛任务使用 Obtain wool，并提供初始剪刀；收获沙子使用 Obtain sand。用户观察到 shear sheep 的热力图更好，这支持开展对照实验，但尚未证明提示词导致零成功。[原论文](https://arxiv.org/html/2410.03618v2)

本地当前 task_specs.yaml 的 test_shear_sheep 两个 prompt 都为 Obtain wool，主手为 shears，主成功条件是得到一个 wool；当前还存在共享 MineCLIP、NACLIP/P85 改动。新环境需要核对官方来源，不能只关闭几个开关就声称原版。

诊断要区分发现羊、靠近/对准、持剪刀正确交互、物品收集。保持原任务成功条件；若原生事件支持，再分项区分剪毛与杀羊获得羊毛。不能悄悄改变主指标。

两个 prompt 字段、MineCLIP 视频上下文、虚拟 zoom 与 U-Net 输入/训练文本都需要核对。已有模型仅换字符串的短评估属于诊断；完整提示词对照需要匹配 U-Net 和策略训练语义。

## 论文筛选

检索截至 2026-10-11，覆盖 arXiv、OpenReview、官方会议论文、作者项目和代码。以下按本项目适用性筛选，并非全网论文的客观排名。

| 论文与时间 | 值得采用的机制 | 适用边界 |
| --- | --- | --- |
| [SAGE](https://arxiv.org/html/2607.17973v2)，2026-07 首发、09-28 v2，预印本；[代码](https://github.com/PKU-ML/SAGE) | 子目标同时条件化动作候选和模型评分；固定底座与搜索预算做消融 | 部分训练依赖专家/控制器数据，原版探索回放不满足该假设；机器人动作输出不能直接迁移 |
| [TTGS](https://ktolnos.github.io/ttgs/)，2025-10 首发、ICML 2026 | 数据状态的子目标检索/搜索，作为轻量规划对照 | 必须先有可靠目标条件策略/距离；Minecraft 视觉相似不等于连通或可达 |
| [HWM](https://arxiv.org/abs/2604.03208)，2026-04 首发、06-16 v2，预印本 | 真实动作片段抽象和多尺度动力学 | 原版已包含长短程分支，需要证明新增作用；首轮扩展原 RSSM，不整体换架构 |
| [H-JEPA](https://arxiv.org/html/2610.06805v1)，2026-10-05，预印本 | 高层慢变化表征、动作敏感性及逆动力学诊断 | 刚发布；先借鉴可验证机制，不能只因预测 loss 低就排除只记背景的退化 |
| [RoboReward](https://arxiv.org/html/2601.00675v2)，2026-01，预印本 | 奖励评价加入失败、部分进展和近成功 | 借鉴评价设计，不直接采用机器人 4B/8B 模型或假定 Minecraft 迁移有效 |
| [WMPA](https://arxiv.org/abs/2610.10932)，2026-10-07，预印本 | 共享评价器选择冻结策略、短时执行后重选 | 主要验证为状态任务且需多策略库，放到后续，不在第一版做集成 |

补充：[OGBench](https://github.com/seohongpark/ogbench)（ICLR 2025）用于 GCBC/GCIQL 对照及能力分项；[Dreamer 4](https://arxiv.org/abs/2509.24527)（2025-09）作为动作条件世界模型背景，预算不同不整体迁移；[CLIP4MC](https://arxiv.org/abs/2303.10571)（2023 首发，基础参考）提醒视频文本相关性还需与完成程度对齐。

本文的 Minecraft 路线是基于论文的方案推断，尚未在本项目验证。

### C03–C05 必做项

- [ ] 先按 episode/世界划分训练、开发、测试，再切片；相邻帧、zoom 不跨划分，测试不参与 prompt/阈值/超参选择和候选库。
- [ ] 先检查 replay 动作约定，再定义 history through t、issued action、observed next frame，不盲用旧 t+1 索引。
- [ ] 区分真实 RGB、虚拟 zoom 与预测。zoom 可提名 ROI，不当真实宏终点；缓存绑定 encoder/checkpoint/预处理，禁止混用不同热图表示的隐状态。
- [ ] 未来真实帧只作离线事后目标，部署不能读本局未来。事实动作不是专家动作，BC 拟合率不是专家准确率。
- [ ] 原回放没有 issued goal 时先学动作片段条件模型，不能把 achieved goal 冒充 commanded goal；新 goal worker 的真实执行才监督目标条件宏模型。
- [ ] 统计独立 episode 与接近、转向、攻击、工具使用等动作覆盖；重复采一条纠偏不增加独立证据。重加权只能由训练集决定并保留不加权对照。
- [ ] 起步冻结原表示/WM，保留原 actor；新低层显式输入目标和剩余预算，适配离散 MineDojo 动作。
- [ ] 检查动作敏感性、静态背景和相机依赖；必要时增加小辅助头及对应消融，不先换整套 JEPA。
- [ ] 明确 env.step/action-repeat 单位，多步模型用真实时长、折扣累计回报和 gamma^duration，正确处理 terminal/truncation。
- [ ] 可信度阈值在开发集固定，与无门控比较；回退原 actor 要报告比例，靠大部分回退获得不退步不能证明新模块有效。
- [ ] 闭环 RSSM 输入本局真实动作，reset 清状态，真实终止后停查询。视觉距离只是辅助，接触/剪毛完成需要原生任务证据。

### C06 实验与门槛

按阶段增加 B0 严格原版；B1 prompt-only；B2 局部目标控制无新宏模型；B3 简单检索/原短程规划；B4 完整方法。B1–B4 同 prompt。新增 KL/辅助损失/门控均有消融，避免一次改变全部模块。

预算起点：先做少量 smoke；初筛至少 3 个训练种子，最终核心对照尽量 5 个。正式每模型每任务每训练种子建议至少 50 局，根据基线波动和目标效应预声明最终数量。此数值不是文献保证的统计门槛，更多评估局不能代替独立训练种子。

主指标为原生成功率、首次成功交互步数、成功曲线/面积；同时报告种子层级区间、wall-clock、推理时延、显存、离线更新和额外预训练/数据。未成功的首次成功时间按删失/未成功处理，不能设 0。

相同任务/种子用于配对，fresh reset 不强求 RGB/位置完全相等；记录起点和顺序，禁止起点筛选、补样到通过或中间最佳帧替换。协议固定后，测试结果不用于继续调参。

旧 T06 的 FAIL 保留。新计划不能借改名绕过旧门槛；若声称旧 T06 达标，仍需满足并运行原协议。阶段推进和论文任务成功证据分别报告。
