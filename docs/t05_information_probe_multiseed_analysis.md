## 下一次实施范围：冻结底座的目标残差worker

### 想做什么

复用已验收的uniform_rows独立无目标BC作为策略底座：服务器 `relevance_map/t04_outputs/train_no_goal_uniform_20261007T012127/latest.pt`，对应验收 `verify_no_goal_uniform_20261007T012218`。保留完整5120维状态输入和原动作接口，冻结底座、WM及目标编码器。

新增小分支，将当前状态投影、真实128维目标和remaining分别整理后，输出12个动作偏好修正量。动作偏好由底座输出加修正量组成；修正最后一层置零，初始动作分布应与底座严格一致。小探针的快照不直接部署为worker。

同时创建相同容量的无目标修正分支，使用相同初始化、真实batch和更新预算；只有目标输入是否为真实目标这一条件不同。只有两套新分支优化器更新，底座不继续BC，以区分额外参数/训练与目标条件的收益。

### 为什么值得做

三种子确认了预测线索，但小探针压缩了当前状态，也改变了初始化、容量和学习率；不能证明原大主干的唯一问题。残差实验保留已经学好的状态策略，检验目标能否给一个强底座增加有用信息；零初始化也消除本轮第0步两组概率不同的解释。

### 能否实现

需要的真实状态、终点目标、下一动作、remaining和划分均在T04缓存中，独立无目标底座已在服务器训练/验收过。本地可以实现模块与独立加载/保存入口，用户在服务器运行；不需要新trajectory、人工阶段标签或额外MineCLIP前向。

### 怎么验证

1. 接口检查：零修正初始分布与底座一致；原动作/剩余步数/因果状态协议不变；冻结模块无更新；只有新分支可训练；格式和依赖身份明确。
2. 短预算对照：第一轮预定两分支各200次更新，每50次评价/保存。比较冻结底座、无目标修正、有目标修正三组，以完整留出NLL、逐局/预算和标签匹配率为主；目标置零/替换仅作评价，不构造新动作标签或强制动作差异loss。最终预算和中间点分别报告，不只看gap最大点。
3. 工程验收：保存/恢复分支优化器、计数、采样和RNG，校验下一次真实更新一致，冻结依赖共享保存；初始/恢复动作分布可复核。
4. 后续T05真实执行：离线结果支持后，验证真实不同目标是否产生有方向的行为差异及实际目标接近改善；采用此前处理渲染波动的重复评估原则，新的worker版本需匹配新的模型身份/条件清单。原参考目标可保留，旧30trial清单不直接换checkpoint继续执行。通过真实低层控制前不进入T06。

这是下一步计划，当前没有目标残差worker实现或可执行命令。若保留强底座后目标增益消失，优先检查表示/实际行为覆盖；若只有短步改善，明确该边界，不能靠宏模型掩盖低层问题。不继续用增加探针种子来代替执行验证。
