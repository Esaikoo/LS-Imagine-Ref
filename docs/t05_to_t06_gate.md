## T06负责什么

T06实现真实宏转移采集器：固定低层版本和执行方式，记录当前状态、发出的目标、实际执行最多16步后的真实终点、累计回报、终止标志和持续时间。即使目标未实现，也保存真实结果。T07再训练宏模型，T08再优化高层；进入T06不等于进入完整1M训练或证明论文贡献。

采集前要确认worker对目标有实际作用，否则宏数据可能只反映目标基本不起作用的低层。工程恢复PASS、离线NLL收益、参考脚本成功都不能替代worker自主执行证据。

## 第一版有限范围的门槛

不要求先完成采木任务，不要求所有目标100%到达，也不要求跨局RSSM或像素严格相同。第一版可限制在当前已标定的世界、初始化流程和两个局部视觉/姿态目标；扩展到新世界、长距离目标或新worker版本需另验，不把本场景结果称为通用导航。

建议在定位并修复worker后，冻结其版本和mode/sample选择，使用当前两个固定目标、32noop+32前缀+最多16控制，预声明三组×两目标×5重复=30次独立fresh reset。最多2400个真实环境步，包含预热与前缀；每目标/组5条历史，不把每帧计为独立样本。随机顺序和动作种子提前固定，使用新的确认随机数，不根据已有试跑选有利次序或执行方式。

| 层面 | 原型确认规则 |
| --- | --- |
| 工程有效 | 全部30次计划、真实历史/动作/终止/遥测、视频及输入身份可核对；错误和提前终止全保留，不重试或补样，缺测不能判通过。 |
| 两目标方向 | 正确目标组的每个目标至少4/5次同时满足自身视觉进展`d_start - d_end > 0`，以及终点`d_assigned < d_other`；不能由目标0的表现代替目标1。 |
| 目标额外作用 | 对每个目标分别计算全部5次的平均自身进展，正确目标组须为正，并高于独立no_goal和swapped_goal两组；报告起点平衡、所有单次结果及波动。 |
| 行为一致性 | 视频和位置/朝向变化与接近指定视觉目标的方向一致；不能仅因共同左转、随机动作更多、挑选最佳中间帧或渲染变化而通过。 |
| 结果边界 | 主测量用真实固定预算终点；早停使用真实最后观测并单列，不伪造满16步。确认前固定判定，失败保留；不声称统计显著、总体成功率提升或语义采木成功。 |

4/5是建议的工程推进规则，不是论文统计阈值。30次只允许在已声明场景中启动小规模T06采集；论文级跨种子/世界泛化、任务收益及同成本对照留给后续阶段。不要仅凭 pooled平均正值或一条漂亮视频推进。

## 当前完成与缺口

- 已完成：因果状态/动作接口、冻结与恢复、独立随机起点工程试跑、两个固定脚本的当前流程可达性与度量标定。
- 尚缺：worker在两个目标上的稳定自主接近、相对无目标/交换组的方向性优势，以及按新完整预声明计划的确认。
- 本轮交付：成功脚本历史上的动作诊断，本地实现完成、服务器待验收；它定位修复方向，不自动批准上述行为门槛或T06。

通过后先实现T06采集和数据检查，核对发出目标、实际终点、步数、低层版本与回报只累计一次，再考虑宏模型；无需在T05反复要求离线loss达到一个任意数值。
